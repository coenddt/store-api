# 02 — 查询参数 → GQL 映射

列表查询 `GET /{resource}` 的全部查询能力来自 GQL 本身，适配层只做**透传与参数绑定**，不发明第二套筛选/排序/分页语法。

## 参数定义（双端一致）

| 查询参数 | 语义 | 映射 |
|---|---|---|
| `q` | GQL 查询体（不含资源头与投影的**条件及之后部分**，见下） | 拼接进 GQL |
| `p.<name>` | 绑定 GQL 中的命名参数 `@<name>` | 收集进 `params` 对象 |

### `q` 的形态

`q` 是 store `query(gql, params)` 的 gql 串中**资源头之后的完整部分**，适配器负责拼上资源头：

```
GET /api/user?q=($condition: @c0, $limit: 10) { name, age }
```

适配器拼接为：`user($condition: @c0, $limit: 10) { name, age }`，等价于直接调用
`store.query('user($condition: @c0, $limit: 10) { name, age }', { c0: {...} })`。

排序、分页、关系展开、聚合等全部走 GQL 自有语法（`$orderby` / `$limit` / `$offset` / 关系子查询 / `$group` 等），本规范不重复定义，以 store 文档（text-to-query / GQL 语法）为准。

### `p.<name>` 的值类型转换（双端必须逐字一致）

所有 `p.*` 值以**字符串**到达，按下列规则转换后绑定（首个命中即止，无命中则保持字符串原样）：

1. `true` / `false` → 布尔
2. `null` → null
3. 完全符合整数正则 `^-?\d+$` → 整数
4. 完全符合浮点正则 `^-?\d+\.\d+$` → 浮点数
5. 其余 → 字符串原样

需要复杂结构（对象/数组）时，值为合法 JSON 则解析为对象，解析失败 ⇒ `400` 并原样报出解析错误（禁静默当字符串兜底）。

同名参数重复出现时（`p.tag=a&p.tag=b`），绑定值为**数组**（每元素各自转换）；单次出现时绑定标量。

### 无 `q` 时

等价于查询全表（GQL 仅资源头 + 投影），返回该资源全部可见记录——是否被权限裁剪由 store RBAC 决定，适配层不追加任何默认条件。

## 错误

- `q` 拼接后经 store 解析失败（GQL 语法错误）⇒ `400`，响应体携带 store 的原始错误信息，原样透传，不改写不圆场。
- `p.*` JSON 解析失败 ⇒ `400`，携带解析错误原文。
