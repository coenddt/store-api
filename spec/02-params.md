# 02 — 查询参数 → GQL 映射

列表查询 `GET /{resource}` 的全部查询能力来自 GQL 本身，适配层只做**透传与参数绑定**，不发明第二套筛选/排序/分页语法。

## 参数定义（双端一致）

| 查询参数 | 语义 | 映射 |
|---|---|---|
| `q` | GQL 查询体（不含资源头与投影的**条件及之后部分**，见下） | 拼接进 GQL |
| `p.<name>` | 绑定 GQL 中的命名参数 `@<name>` | 收集进 `params` 对象 |
| `field` | 资源字节子路由（`GET`/`POST /{resource}/{id}/file`）的字段点路径 | 定位记录上承载资源引用的字段；缺省回落适配器选项 `fileField` |

### `field` 的形态与边界

- `field` 为**点路径**（如 `images.full` / `file`），逐段取对象属性；缺省（不传）时用适配器选项 `fileField`。
- 仅支持点路径寻址（`a.b`）；**不支持**数组下标 / 通配 / 表达式。
- 路径任一段缺失 ⇒ 视同「文件字段为空」⇒ 404 `NOT_FOUND`（与 `fileField` 缺失同判定）。
- 该参数**仅**对 file 子路由生效；列表 / 单条路由忽略之（不报错）。

### `q` 的形态

`q` 是 store `query(gql, params)` 的 gql 串中**资源头之后的完整部分**，适配器负责拼上资源头：

```
GET /api/user?q=($condition: @c0, $limit: @l) { name, age }&p.l=10
```

适配器拼接为：`user($condition: @c0, $limit: @l) { name, age }`，等价于直接调用
`store.query('user($condition: @c0, $limit: @l) { name, age }', { c0: {...}, l: 10 })`。

> **GQL 参数值一律是 `@name` 命名引用**（core GQL 语法，py-store / nodejs-store 同构），
> **不接受字面量**——数值、布尔、对象等都经 `p.<name>` 传入后在 params 侧转型（见下节）。
> 本示例曾误写为 `$limit: 10` 字面量形态（v1 修订更正），照写会被 core 以 `ERR_GQL_PARSE:` 拒绝。

排序、分页、关系展开、聚合等全部走 GQL 自有语法（`$orderby` / `$limit` / `$offset` / 关系子查询 / `$group` 等），本规范不重复定义，以 store 文档（text-to-query / GQL 语法）为准。

### `p.<name>` 的值类型转换（双端必须逐字一致）

所有 `p.*` 值以**字符串**到达，按下列规则转换后绑定（首个命中即止，无命中则保持字符串原样）：

1. `true` / `false` → 布尔
2. `null` → null
3. 完全符合整数正则 `^-?\d+$` → 整数
4. 完全符合浮点正则 `^-?\d+\.\d+$` → 浮点数
5. 其余 → 字符串原样

需要复杂结构（对象/数组）时，值为合法 JSON 则解析为对象，解析失败 ⇒ `400` 并原样报出解析错误（禁静默当字符串兜底）。

同名参数重复出现时（`p.tag=a&p.tag=b`），绑定值为**数组**（每元素各自转换）；单次出现时绑定标量。

### 无 `q` 时

适配器**生成全字段投影**（取 schema `fields` 键列表）——否则（无投影）契约语义是只返回 `_id` 列表。是否被权限裁剪由 store RBAC 决定，适配层不追加任何默认条件。

### 投影契约（重要）

GQL **省略投影段 = 只返回 `_id`**（三端一致的 core 契约，非「返回全字段」）。`q` 存在时投影完全由 `q` 决定（`q` 未写投影 = 只要 `_id`，符合 GQL 语义，适配层不干预、不追加）；投影缺失的后果在响应中立即可见（data 只含 `_id`），不静默兜底。单条路由与无 `q` 列表路由的投影由适配器显式生成（见 01-routing）。

## 错误

- `q` 拼接后经 store 解析失败（GQL 语法错误）⇒ `400`，响应体携带 store 的原始错误信息，原样透传，不改写不圆场。
- `p.*` JSON 解析失败 ⇒ `400`，携带解析错误原文。
